## 기술 개념

### 1. PWA (Progressive Web App)란?

단순 "홈 화면에 추가"와 PWA의 차이점:

| 구분          | 홈 화면 추가만           | PWA                              |
| ------------- | ------------------------ | -------------------------------- |
| 오프라인      | 작동 안 함               | **작동함** (Service Worker 캐싱) |
| 설치 프롬프트 | 없음                     | 브라우저가 자동 표시             |
| 앱 UI         | 브라우저 UI 보일 수 있음 | 완전한 standalone 모드           |
| 스플래시 화면 | 없음                     | 있음                             |
| 업데이트      | 수동 새로고침            | 자동 백그라운드 업데이트         |

**단어 암기 앱에서 PWA가 중요한 이유:**

- 지하철, 비행기 등 오프라인 환경에서 자주 사용
- 단어 데이터가 캐싱되어 인터넷 없이도 학습 가능

### 2. PWA 캐싱 구조

이 프로젝트의 단어 데이터 캐싱 방식:

```
[빌드 시]
src/data/words-*.ts (TypeScript)
    ↓ Vite 빌드
dist/assets/index-xxxx.js (번들에 포함)
    ↓ Service Worker
브라우저 Cache Storage (오프라인 사용 가능)
```

**vite.config.ts 설정:**

```typescript
VitePWA({
  registerType: "autoUpdate",
  workbox: {
    // JS, CSS, HTML 등을 캐싱
    globPatterns: ["**/*.{js,css,html,ico,png,svg,woff2}"],
    runtimeCaching: [
      // 외부 폰트도 캐싱
      { urlPattern: /^https:\/\/fonts\.googleapis\.com\/.*/, ... }
    ]
  },
  manifest: {
    name: "단어의 신 GRE",
    display: "standalone",  // 브라우저 UI 숨김
    // ...
  }
})
```

**캐싱 확인 방법:**

1. F12 → Application 탭
2. Cache Storage 섹션
3. `workbox-precache-...` 항목 확인

### 3. Firebase Auth: signInWithPopup vs signInWithRedirect

| 방식                 | 동작                        | 장단점                                     |
| -------------------- | --------------------------- | ------------------------------------------ |
| `signInWithRedirect` | 페이지 리다이렉트 후 로그인 | 모바일에서 안정적이나 로컬 환경에서 불안정 |
| `signInWithPopup`    | 팝업 창에서 로그인          | 로컬/프리뷰 환경에서 안정적                |

**문제 상황:**

- `signInWithRedirect` 사용 시 로컬 preview에서 로그인 후 상태 유실
- 로딩 화면 → 다시 로그인 페이지로 돌아가는 현상

**해결:**

```typescript
// Before
await signInWithRedirect(auth, googleProvider);

// After
await signInWithPopup(auth, googleProvider);
```

### 7. Firestore vs SQL Database

| 구분   | SQL Database          | Firestore                      |
| ------ | --------------------- | ------------------------------ |
| 구조   | 테이블 + 행(row)      | 컬렉션 + 문서(document)        |
| 스키마 | 고정 (컬럼 미리 정의) | 유연 (문서마다 다른 필드 가능) |
| 관계   | JOIN으로 테이블 연결  | 중첩 데이터 또는 참조          |
| 쿼리   | SQL 언어              | 메서드 체이닝                  |

**Firestore 특징:**

- NoSQL 문서 데이터베이스
- 실시간 동기화 (`onSnapshot`)
- 서버리스 (서버 관리 불필요)
- 오프라인 지원 (로컬 저장 후 나중에 동기화)

**코드 비교:**

```sql
-- SQL
SELECT * FROM users WHERE id = 'user123';
```

```typescript
// Firestore
const snap = await getDoc(doc(db, "users", "user123"));
```

### 8. Service Worker란?

브라우저 백그라운드에서 실행되는 스크립트로, 웹페이지와 서버 사이에서 요청을 가로챕니다.

```
[일반 웹페이지]
브라우저 ←→ 서버

[Service Worker 있을 때]
브라우저 ←→ Service Worker ←→ 서버
                  ↓
            Cache Storage
```

**주요 기능:**

- 오프라인 캐싱 (파일 저장 후 인터넷 없이 제공)
- 백그라운드 동기화
- 푸시 알림
- 자동 업데이트

**확인 방법:** F12 → Application → Service Workers

### 9. UTC 시간 vs 로컬 시간

**UTC (Coordinated Universal Time):** 전 세계 공통 기준 시간

```
영국 런던 = UTC ± 0
한국 (KST) = UTC + 9시간
미국 뉴욕 = UTC - 5시간
```

**문제점:** `toISOString()`은 UTC 기준으로 변환됨

```javascript
// 한국 시간 2026-01-25 오전 8시
new Date()
  .toISOString()
  // → "2026-01-24T23:00:00.000Z" (UTC)

  .split("T")[0];
// → "2026-01-24" ← 전날 날짜!
```

**해결:** 로컬 시간 기준 유틸리티 함수 사용

```typescript
// src/lib/date.ts
export function getLocalDateString(date: Date = new Date()): string {
  const year = date.getFullYear();
  const month = String(date.getMonth() + 1).padStart(2, "0");
  const day = String(date.getDate()).padStart(2, "0");
  return `${year}-${month}-${day}`;
}

export function getTodayString(): string {
  return getLocalDateString(new Date());
}
```

### 11. Web Speech API (음성 합성)

브라우저에서 텍스트를 음성으로 변환하는 API입니다.

```typescript
function speakWord(word: string) {
  speechSynthesis.cancel(); // 이전 발음 중지

  const utterance = new SpeechSynthesisUtterance(word);
  utterance.lang = "en-US"; // 언어 설정
```

### 12. React 순수성 규칙 (Purity Rules)

React 컴포넌트와 훅은 **순수 함수**여야 합니다. 같은 입력에 항상 같은 출력을 반환해야 합니다.

**문제 코드:**

```typescript
// useMemo 안에서 Math.random() 호출 - 순수성 위반!
const studyWords = useMemo(() => {
  const shuffled = [...words];
  for (let i = shuffled.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1)); // 에러 발생
    [shuffled[i], shuffled[j]] = [shuffled[j], shuffled[i]];
  }
  return shuffled;
}, [words]);
```

**에러 메시지:**

```
Cannot call impure function during render.
Math.random is an impure function.
```

**해결 방법:** 모듈 레벨에서 미리 셔플 순서 생성

```typescript
// 컴포넌트 외부에서 한 번만 실행 (렌더링 사이클 외부)
function createShuffledIndices(length: number): number[] {
  const indices = Array.from({ length }, (_, i) => i);
  for (let i = indices.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [indices[i], indices[j]] = [indices[j], indices[i]];
  }
  return indices;
}
const SHUFFLED_ORDER = createShuffledIndices(words.length);

// 컴포넌트 내부에서는 미리 생성된 순서만 참조
const studyWords = useMemo(() => {
  // SHUFFLED_ORDER를 사용하여 정렬 (Math.random 호출 없음)
  return SHUFFLED_ORDER.filter((idx) => newWordIds.has(words[idx].id)).map((idx) => words[idx]);
}, [newWordIds]);
```

### 13. useEffect에서 setState 호출 경고

**문제:**

```typescript
useEffect(() => {
  setStudyWords([...reviewWords, ...shuffledNewWords]);
}, [userData.progress]);
```

**에러 메시지:**

```
Calling setState synchronously within an effect can trigger cascading renders.
```

**왜 문제인가?**

- useEffect는 외부 시스템과 동기화하기 위한 것
- 렌더링 → useEffect → setState → 재렌더링 → 성능 저하
- cascading renders (연쇄 렌더링) 발생

**올바른 접근:**

1. `useMemo`로 파생 상태 계산 (권장)
2. 외부 시스템 구독 시에만 useEffect 내 setState 사용
3. 모듈 레벨에서 부수 효과(Math.random 등) 처리

### 14. Fisher-Yates Shuffle 알고리즘

배열을 무작위로 섞는 표준 알고리즘입니다.

```typescript
function shuffle<T>(array: T[]): T[] {
  const result = [...array];
  for (let i = result.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [result[i], result[j]] = [result[j], result[i]];
  }
  return result;
}
```

**특징:**

- 시간 복잡도: O(n)
- 모든 순열이 동일한 확률로 발생 (편향 없음)
- in-place 수정 가능

**학습 앱에서 랜덤 순서의 장점:**

- 위치 기억에 의존하지 않고 실제 단어 암기
- 매번 다른 순서로 학습하여 지루함 방지

### 15. Vercel Serverless Functions

Vercel에서 백엔드 API를 만드는 방법입니다. `/api` 폴더에 파일을 생성하면 자동으로 서버리스 함수가 됩니다.

**프로젝트 구조:**

```
├── src/           # 프론트엔드 (React)
├── api/           # 백엔드 (Serverless Functions)
│   └── tts.ts     # → https://your-app.vercel.app/api/tts
└── package.json
```

**기본 코드 구조:**

```typescript
// api/tts.ts
import type { VercelRequest, VercelResponse } from "@vercel/node";

export default async function handler(req: VercelRequest, res: VercelResponse) {
  const { text } = req.query;  // URL 파라미터 (?text=hello)
  // req.body   - POST 요청 바디
  // req.method - GET, POST, PUT, DELETE 등

  // API 로직 처리
  res.status(200).json({ message: "Hello" });
}
```

**왜 필요한가? - API 키 보호:**

```typescript
// ❌ 프론트엔드에서 직접 호출 - API 키 노출!
fetch(`https://api.google.com/tts?key=SECRET_KEY`)

// ✅ 서버리스 함수 경유 - API 키 숨김
fetch("/api/tts?text=hello")  // 서버에서 SECRET_KEY 사용
```

**특징:**

| 항목 | 설명 |
|------|------|
| 자동 스케일링 | 요청 많으면 자동 확장 |
| 콜드 스타트 | 첫 요청 시 약간 느림 (~500ms) |
| 실행 시간 | 최대 10초 (Hobby), 60초 (Pro) |
| 환경변수 | Vercel Dashboard에서 설정 |

**프론트엔드에서 호출:**

```typescript
fetch("/api/tts?text=hello");
```

**로컬 테스트 방법:**

```bash
# Vercel CLI 설치
npm i -g vercel

# 로컬에서 서버리스 함수 포함 실행
vercel dev
```

> **주의:** `npm run dev` (Vite)로는 `/api` 경로가 작동하지 않습니다.
> 배포 후 또는 `vercel dev`로 테스트해야 합니다.

```typescript
const response = await fetch(`https://texttospeech.googleapis.com/v1/text:synthesize?key=${apiKey}`, {

    input: { text: "hello" },

      languageCode: "en-US",
```

- 앱 삭제 후 재설치

## 성능 최적화 학습 (저녁)

### 19. DNS Prefetch vs Preconnect

브라우저가 외부 리소스에 미리 연결을 준비하는 두 가지 방법.

| 구분 | dns-prefetch | preconnect |
|------|-------------|------------|
| 수행 작업 | DNS 조회만 | DNS + TCP + TLS 핸드셰이크 |
| 절약 시간 | 20-120ms | 100-500ms |
| 사용 시점 | 나중에 사용할 수도 있는 도메인 | 확실히 사용할 중요한 도메인 |

```html
<!-- DNS Prefetch: 가벼움, 광범위하게 사용 -->
<link rel="dns-prefetch" href="//googleapis.com" />

<!-- Preconnect: 무거움, 중요한 도메인에만 -->
<link rel="preconnect" href="https://firestore.googleapis.com" crossorigin />
```

### 20. 폰트 비동기 로딩 (Async Font Loading)

폰트 CSS가 렌더링을 차단하지 않도록 비동기로 로드하는 기법.

```html
<!-- preload + onload 패턴 -->
<link
  rel="preload"
  href="font.css"
  as="style"
  onload="this.onload=null;this.rel='stylesheet'"
/>

<!-- JavaScript 비활성화 환경 폴백 -->
<noscript>
  <link rel="stylesheet" href="font.css" />
</noscript>
```

**원리:**
- `preload`: 리소스를 미리 다운로드하지만 적용하지 않음
- `onload`: 로드 완료 시 `rel='stylesheet'`로 변경하여 적용
- `this.onload=null`: 무한 루프 방지

### 21. Vendor 청크 분리 (Manual Chunks)

Vite/Rollup에서 라이브러리를 별도 청크로 분리하여 캐싱 효율을 높이는 방법.

```typescript
// vite.config.ts
build: {
  rollupOptions: {
    output: {
      manualChunks: {
        "vendor-react": ["react", "react-dom", "react-router-dom"],
        "vendor-firebase": ["firebase/app", "firebase/auth", "firebase/firestore"],
      },
    },
  },
},
```

**효과:**
- 앱 코드 변경 시 vendor 청크는 캐시 유지
- 재방문 시 다운로드 용량 감소

### 22. FCP와 LCP 최적화

| 지표 | 의미 | 기준 |
|------|------|------|
| FCP (First Contentful Paint) | 첫 콘텐츠가 화면에 그려지는 시점 | < 1.8초 |
| LCP (Largest Contentful Paint) | 가장 큰 콘텐츠가 그려지는 시점 | < 2.5초 |

**최적화 방법 (Auth 로딩):**

```tsx
// Before: 인증 확인 중 스피너 표시 → FCP 지연
if (authLoading) return <Spinner />;
if (!user) return <Login />;

// After: 즉시 Login 표시 → FCP 개선
if (!user) return <Login />;  // authLoading 상태와 무관하게 즉시 렌더링
if (dataLoading) return <Spinner />;
```

### 23. 접근성 - 시맨틱 랜드마크

스크린 리더 사용자가 페이지 구조를 파악할 수 있도록 의미 있는 HTML 태그 사용.

```tsx
// Bad
<div className="header">...</div>

// Good
<main>
  <header>...</header>
  <nav aria-label="주요 메뉴">...</nav>
</main>
```

### 24. 캐시 헤더 설정

정적 자산에 장기 캐시를 설정하여 재방문 시 다운로드를 최소화.

```json
// vercel.json
{
  "headers": [
    {
      "source": "/assets/(.*)",
      "headers": [
        { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }
      ]
    }
  ]
}
```

- `max-age=31536000`: 1년 (초 단위)
- `immutable`: 만료 전 재검증 불필요
