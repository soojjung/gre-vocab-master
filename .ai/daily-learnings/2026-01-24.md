## 기술 개념

### 1. PWA (Progressive Web App)란?

단순 "홈 화면에 추가"와 PWA의 차이점:

| 구분 | 홈 화면 추가만 | PWA |
|------|---------------|-----|
| 오프라인 | 작동 안 함 | **작동함** (Service Worker 캐싱) |
| 설치 프롬프트 | 없음 | 브라우저가 자동 표시 |
| 앱 UI | 브라우저 UI 보일 수 있음 | 완전한 standalone 모드 |
| 스플래시 화면 | 없음 | 있음 |
| 업데이트 | 수동 새로고침 | 자동 백그라운드 업데이트 |

**단어 암기 앱에서 PWA가 중요한 이유:**
- 지하철, 비행기 등 오프라인 환경에서 자주 사용
- 단어 데이터가 캐싱되어 인터넷 없이도 학습 가능

### 2. PWA 캐싱 구조

이 프로젝트의 단어 데이터 캐싱 방식:

```
[빌드 시]
src/data/words-*.ts (TypeScript)
    ↓ Vite 빌드
dist/assets/index-xxxx.js (번들에 포함)
    ↓ Service Worker
브라우저 Cache Storage (오프라인 사용 가능)
```

**vite.config.ts 설정:**

```typescript
VitePWA({
  registerType: "autoUpdate",
  workbox: {
    // JS, CSS, HTML 등을 캐싱
    globPatterns: ["**/*.{js,css,html,ico,png,svg,woff2}"],
    runtimeCaching: [
      // 외부 폰트도 캐싱
      { urlPattern: /^https:\/\/fonts\.googleapis\.com\/.*/, ... }
    ]
  },
  manifest: {
    name: "단어의 신 GRE",
    display: "standalone",  // 브라우저 UI 숨김
    // ...
  }
})
```

**캐싱 확인 방법:**
1. F12 → Application 탭
2. Cache Storage 섹션
3. `workbox-precache-...` 항목 확인

### 3. Firebase Auth: signInWithPopup vs signInWithRedirect

| 방식 | 동작 | 장단점 |
|------|------|--------|
| `signInWithRedirect` | 페이지 리다이렉트 후 로그인 | 모바일에서 안정적이나 로컬 환경에서 불안정 |
| `signInWithPopup` | 팝업 창에서 로그인 | 로컬/프리뷰 환경에서 안정적 |

**문제 상황:**
- `signInWithRedirect` 사용 시 로컬 preview에서 로그인 후 상태 유실
- 로딩 화면 → 다시 로그인 페이지로 돌아가는 현상

**해결:**
```typescript
// Before
await signInWithRedirect(auth, googleProvider);

// After
await signInWithPopup(auth, googleProvider);
```

### 4. Vercel 배포 시 환경 변수 설정

Vite 프로젝트를 Vercel에 배포할 때:

1. **환경 변수 prefix**: `VITE_` 접두사 필수
2. **Vercel 대시보드**: Settings → Environment Variables에 추가
3. **Firebase 도메인 등록**: 배포된 URL을 Firebase Console → Authentication → Authorized domains에 추가

```
필수 환경 변수:
VITE_FIREBASE_API_KEY
VITE_FIREBASE_AUTH_DOMAIN
VITE_FIREBASE_PROJECT_ID
VITE_FIREBASE_STORAGE_BUCKET
VITE_FIREBASE_MESSAGING_SENDER_ID
VITE_FIREBASE_APP_ID
VITE_FIREBASE_MEASUREMENT_ID
```

### 5. npm 버전 명시 (Caret ^)

`package.json`의 버전 표기:

```json
"react": "^19.2.0"
```

| 표기 | 의미 | 예시 |
|------|------|------|
| `^19.2.0` | 19.x.x 최신 버전 | 19.2.0 ~ 19.9.9 |
| `~19.2.0` | 19.2.x 최신 버전 | 19.2.0 ~ 19.2.9 |
| `19.2.0` | 정확히 이 버전만 | 19.2.0 |

**실제 설치 버전 확인:**
```bash
npm list react  # 설치된 버전 확인
```

### 6. Firebase Console

Firebase 프로젝트를 관리하는 웹 대시보드 (https://console.firebase.google.com)

**주요 메뉴:**

| 메뉴 | 기능 |
|------|------|
| Authentication → Users | 가입한 사용자 목록 조회/삭제 |
| Authentication → Settings | 로그인 방법, 승인된 도메인 관리 |
| Firestore → Data | 저장된 데이터 조회/수정 |
| Firestore → Rules | 보안 규칙 설정 |
| Project Settings | API 키, 프로젝트 ID 확인 |

### 7. Firestore vs SQL Database

| 구분 | SQL Database | Firestore |
|------|--------------|-----------|
| 구조 | 테이블 + 행(row) | 컬렉션 + 문서(document) |
| 스키마 | 고정 (컬럼 미리 정의) | 유연 (문서마다 다른 필드 가능) |
| 관계 | JOIN으로 테이블 연결 | 중첩 데이터 또는 참조 |
| 쿼리 | SQL 언어 | 메서드 체이닝 |

**Firestore 특징:**
- NoSQL 문서 데이터베이스
- 실시간 동기화 (`onSnapshot`)
- 서버리스 (서버 관리 불필요)
- 오프라인 지원 (로컬 저장 후 나중에 동기화)

**코드 비교:**

```sql
-- SQL
SELECT * FROM users WHERE id = 'user123';
```

```typescript
// Firestore
const snap = await getDoc(doc(db, "users", "user123"));
```

### Q2. `package.json`에서 `"react": "^19.2.0"`의 의미는?

- A) 정확히 19.2.0 버전만 설치
- B) 19.2.x 범위의 최신 버전 설치
- C) 19.x.x 범위의 최신 버전 설치
- D) 20.0.0 미만의 모든 버전 설치

<details>
<summary>정답 보기</summary>

**C) 19.x.x 범위의 최신 버전 설치**

`^`(caret)는 major 버전이 같은 범위에서 최신 버전을 설치합니다.
- `^19.2.0` → 19.0.0 이상, 20.0.0 미만

</details>

### Q3. Firebase 로그인에서 `signInWithRedirect` 대신 `signInWithPopup`을 사용한 이유는?

- A) 보안이 더 강력해서
- B) 로컬/preview 환경에서 더 안정적이라서
- C) 코드가 더 짧아서
- D) 모바일에서만 작동해서

<details>
<summary>정답 보기</summary>

**B) 로컬/preview 환경에서 더 안정적이라서**

`signInWithRedirect`는 페이지 리다이렉트 과정에서 상태가 유실될 수 있어, 로컬 환경에서 로그인 후 다시 로그인 페이지로 돌아가는 문제가 발생했습니다.

</details>

### Q4. Firestore의 데이터 구조 단위는?

- A) 테이블과 행(row)
- B) 컬렉션과 문서(document)
- C) 스키마와 레코드
- D) 버킷과 객체

<details>
<summary>정답 보기</summary>

**B) 컬렉션과 문서(document)**

Firestore는 NoSQL 문서 데이터베이스로, 컬렉션 안에 문서(JSON 형태)를 저장합니다.

</details>
