### 1. React Hook의 본질: "공유되는 전역 상태"가 아니라 "재사용 가능한 로직"

> **핵심 개념:** Hook은 상태를 공유하는 것이 아니라, 상태 관리 **로직**을 재사용하는 것이다.

```tsx
// useCounter 훅 정의
function useCounter() {
  const [count, setCount] = useState(0);
  return { count, setCount };
}

// ComponentA에서 호출
function ComponentA() {
  const { count } = useCounter(); // count A (독립적인 state)
}

// ComponentB에서 호출
function ComponentB() {
  const { count } = useCounter(); // count B (A와 완전히 별개!)
}
```

**같은 훅을 호출해도 각 컴포넌트는 자신만의 독립적인 state를 갖는다.**

```
App
├── HomePage (useUserData 호출)
│   └── useState → state A: {dailyGoal: 25}
│
├── StudyPage (useUserData 호출)
│   └── useState → state B: {dailyGoal: 25}  ← 별도의 state!
│
└── QuizPage (useUserData 호출)
    └── useState → state C: {dailyGoal: 25}  ← 또 다른 별도의 state!
```

**상태를 공유하려면 Context가 필요하다.**

### 2. Context로 상태 공유하기

**문제 상황:**
- 여러 페이지에서 같은 훅(`useUserData`)을 각각 호출
- 각 페이지마다 독립적인 인스턴스가 생성되어 상태가 공유되지 않음
- 페이지 이동 시마다 데이터를 다시 로드

**해결책:**
- React Context로 단일 인스턴스를 생성하고 전체 앱에서 공유

```tsx
// Context 생성
const UserDataContext = createContext<UserDataContextType | null>(null);

// Provider 컴포넌트
export function UserDataProvider({ userId, children }: Props) {
  const userDataHook = useUserData(userId); // 한 번만 호출
  return (
    <UserDataContext.Provider value={userDataHook}>
      {children}
    </UserDataContext.Provider>
  );
}

// 사용하는 컴포넌트
function MyComponent() {
  const { userData } = useUserDataContext(); // Context에서 가져옴
}
```

### 3. 비동기 저장의 Race Condition 문제

**문제 시나리오:**
```
1. Page A: 데이터 로드 → state = {goal: 25}
2. 사용자가 설정 변경 → state = {goal: 30}
3. Page A: 저장 시작 (비동기, await 안함)
4. 사용자가 Page B로 이동
5. Page B: 새 인스턴스 생성, DB에서 로드 → 아직 저장 안됨! → {goal: 25}
6. Page A: 저장 완료 → DB = {goal: 30}
7. Page B: state는 여전히 {goal: 25}
8. Page B에서 변경 시 → {goal: 25}로 덮어씀!
```

**핵심 원인:**
- Fire-and-forget 패턴 (저장 완료를 기다리지 않음)
- 여러 독립적인 인스턴스가 서로의 상태를 모름
- 새 페이지가 저장 완료 전에 로드해서 이전 데이터 받음

**해결책:**
1. Context로 단일 인스턴스 사용 (페이지 이동해도 다시 로드 안함)
2. 저장 중 플래그(`isSaving.current`)로 로드 방지

```tsx
const isSaving = useRef(false);

// 저장 중이면 로드하지 않음
if (isSaving.current) {
  console.log("Skip loading - save in progress");
  return;
}
```

### 4. Supabase upsert와 onConflict 옵션

**upsert란?**
- INSERT + UPDATE의 합성어
- 데이터가 없으면 INSERT, 있으면 UPDATE

**onConflict 옵션:**
- 충돌 판단 기준이 되는 컬럼 지정
- 해당 컬럼 값이 같으면 UPDATE 수행

```tsx
await supabase
  .from("user_data")
  .upsert(row, { onConflict: "user_id" }); // user_id가 같으면 UPDATE
```

### 5. iOS Capacitor 앱 디버깅 (Safari Web Inspector)

**설정 방법:**

1. **Mac Safari 설정**
   - Safari > 설정 > 고급 > "메뉴 막대에서 개발자용 메뉴 보기" 체크

2. **iOS 기기 설정**
   - 설정 > Safari > 고급 > "웹 검사기" 활성화

3. **디버깅 연결**
   - Xcode에서 앱 실행
   - Safari 메뉴바 > 개발자용 > 시뮬레이터/기기 선택
   - 콘솔 탭에서 JavaScript 로그 확인
