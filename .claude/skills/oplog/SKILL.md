`.ai/OPERATIONS_LOG.md` 의 형식에 맞춰 운영 이슈를 새 항목으로 추가합니다. 기존 항목 위에 삽입하고, 자동 커밋은 하지 않습니다 (사용자 검토 후 직접 커밋).

## 작업 흐름

1. **사용자에게 6개 필드 질문** (이미 메시지에 정보가 있으면 추출, 없으면 한 번에 묻기):
   - **요약** (제목용 한 줄)
   - **발견 경로**: 누가 / 어떻게 발견했는지 (예: 사용자 리뷰 댓글, Sentry 알람, 본인 테스트)
   - **영향**: 어떤 사용자/환경/기능에 어떻게 영향
   - **원인**: 기술적 root cause
   - **해결**: 무엇을 어떻게 처리했는지
   - **후속 조치**: 재발 방지/모니터링/문서화 등 부수 작업
   - **교훈**: 일반화 가능한 학습 (선택, 없으면 생략 가능)
   - **관련 커밋 SHA** (선택)

2. **현재 날짜 확인**: `date +%Y-%m-%d` 로 오늘 날짜 (KST 기준이면 사용자 환경 따름)

3. **`.ai/OPERATIONS_LOG.md` 파싱**:
   - 첫 `---` 구분자 다음, 가장 최근 `## ` 헤더 직전에 새 항목 삽입
   - 기존 형식과 동일한 표 구조 유지

4. **새 항목 형식** (그대로 따를 것):

   ```markdown
   ## YYYY-MM-DD — {요약}

   | 항목 | 내용 |
   |---|---|
   | **발견 경로** | {발견 경로} |
   | **영향** | {영향} |
   | **원인** | {원인} |
   | **해결** | {해결} |
   | **후속 조치** | {후속 조치} |
   | **교훈** | {교훈} |

   관련 커밋: `{SHA}` ({SHA 설명})

   ---
   ```

   - 표 셀 내 줄바꿈은 `<br>` 사용
   - 다중 항목은 `- ` 리스트 또는 `<br>` 구분
   - "관련 커밋" 줄은 SHA 없으면 생략

5. **삽입 후**:
   - 변경된 파일 경로와 추가된 내용을 사용자에게 보고
   - **절대 자동 커밋 X**. "검토 후 직접 commit 해주세요" 안내
   - 교훈이 일반화될 만하면 하단의 "운영 점검 체크리스트" 항목 추가 제안 (강제하지 말 것)

## 사용자 입력 패턴

### 정보가 메시지에 충분히 있을 때
사용자: `/oplog 어제 발생한 Vercel 빌드 실패. 원인은 환경변수 누락이었고, Vercel 에 SENTRY_AUTH_TOKEN 추가하니 해결됨.`
→ 6필드 추출 가능한 만큼 채우고, 빠진 필드는 한 번에 묶어서 질문.

### 정보 부족 시
사용자: `/oplog`
→ 6필드를 번호 매겨 한 번에 질문. 사용자가 답하면 그대로 채워서 작성.

## 주의사항

- **OPERATIONS_LOG.md 의 기존 형식 (표 6필드, `## YYYY-MM-DD — 요약` 헤더, `---` 구분자) 을 임의로 바꾸지 말 것**
- 새 항목은 항상 **최상단** 에 삽입. 기존 항목들은 건드리지 말 것
- 작성 후 자동 커밋 금지 (`feedback_commit_only_when_explicitly_asked` 메모리 참조)
- 사용자가 질문에 답하지 않은 필드는 추측해서 채우지 말고, 비워두거나 "(미상)" 표기 후 사용자에게 보충 요청
