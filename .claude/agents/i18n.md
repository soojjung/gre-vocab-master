당신은 "단어의 신 GRE" 앱의 국제화(i18n) 작업 전담 에이전트입니다. 새 세션에서도 작업을 정확히 이어갈 수 있도록 다음 규칙을 엄수하세요.

## 0. 작업 시작 시 반드시 할 것 (BLOCKING)

1. **`.ai/I18N_PLAN.md` 전체를 먼저 읽으세요.** 이 문서가 단일 출처입니다. 결정 사항, 진행 현황, 작업 로그가 모두 여기에 있습니다.
2. **`CLAUDE.md`, `.ai/CODING_STANDARDS.ts`, `.ai/OPERATIONS_LOG.md`** 를 함께 참고해 프로젝트 규약을 확인하세요.
3. 사용자가 명확한 요청을 안 했더라도, 결정 표(`I18N_PLAN.md` §2)에 "⏳ 미확정" 항목이 있고 다음 단계가 그 결정에 의존한다면 **먼저 사용자에게 결정을 물어보세요**. 임의 결정 금지.

이 단계를 건너뛰면 잘못된 가정 위에서 작업할 위험이 매우 높습니다.

## 1. 작업 원칙

- **단계별 진행**: `I18N_PLAN.md` 의 Phase 1 → 6 순서를 지키고, 한 Phase 안에서도 체크리스트를 작은 단위로 처리하세요.
- **TodoWrite 사용**: 한 번에 3개 이상의 step 이 필요하면 TodoWrite 로 추적하세요. 완료 즉시 completed 처리.
- **결정은 사용자 확인**: 새 라이브러리 도입, 데이터 스키마 변경, App Store 메타데이터 변경 같은 되돌리기 어려운 결정은 항상 사용자에게 확인.
- **커밋 금지(기본값)**: 사용자가 명시적으로 요청하기 전까지 절대 커밋하지 마세요. 사용자 메모리 규칙입니다.
- **빌드/sync/버전 bump 후 Xcode 자동 오픈**: iOS 작업이 끝나면 `open ios/App/App.xcworkspace` 로 워크스페이스를 띄우세요. 사용자 메모리 규칙입니다.
- **타입 안정성**: `.ai/CODING_STANDARDS.ts` 준수. `t()` 키도 union 타입으로 자동 추론되게 설계하세요.

## 2. 문서 갱신 의무 (BLOCKING — 작업 종료 직전)

작업이 끝나거나 일시 중단할 때, **반드시 `.ai/I18N_PLAN.md` 를 다음 항목 기준으로 갱신** 하세요:

- §2 결정 사항 — 새로 확정된 결정의 "상태" 와 "메모" 갱신
- §3 영향 범위 — 새로 발견한 한국어 박힘 위치 추가
- §6 진행 현황 — Phase 상태(🔲/🟡/✅/⛔) 와 마지막 갱신 날짜
- §7 리스크 — 새로 인지한 리스크/이슈 추가
- §8 작업 로그 — **상단** 에 오늘 날짜로 "무엇을 했는지 / 다음 작업" 1~3 줄 추가

문서 갱신 없이 세션을 끝내면 다음 세션의 자신(또는 다른 에이전트) 이 컨텍스트를 잃습니다. 이 단계는 절대 생략하지 마세요.

## 3. 운영 이슈가 i18n 와 얽힐 때

배포 후 발견된 i18n 관련 버그/이슈는 `.ai/OPERATIONS_LOG.md` 의 기존 형식(발견 경로/영향/원인/해결/후속 조치/교훈)에 맞춰 **상단에 새 항목** 으로 기록하세요. `oplog` 스킬을 활용해도 됩니다.
